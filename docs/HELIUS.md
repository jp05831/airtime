# Mainnet notifications and reconciliation

1. Obtain Helius mainnet RPC/DAS access. Set `SOLANA_RPC_URL` and server-only `HELIUS_API_KEY`. The backend checks Solana mainnet genesis and finalized commitment. DAS `searchAssets` is candidate discovery ONLY; each coin is proved via official Pump accounts. Some creator/fee-recipient coins will not be returned by metadata search; manual mint entry remains supported.
2. Configure an authenticated transaction webhook to `https://FINAL_DOMAIN/api/webhooks/helius`. Subscribe to the configured `CAMPAIGN_PAYMENT_WALLET`; optional additional subscribed creator wallets are operational coverage, never automatic fund access. Use the exact `HELIUS_WEBHOOK_SECRET` authorization header agreed with the provider. Requests are authenticated using constant-time comparison, bounded to 1 MB/100 signatures and deduplicated by signature. Webhook amounts/mints/wallet claims are never trusted.
3. Schedule `GET` or `POST https://FINAL_DOMAIN/api/worker` every five minutes with `Authorization: Bearer CRON_SECRET`. `vercel.json` supports this on a plan that permits five-minute cron; an authenticated external scheduler is also supported. Remove the Vercel cron block when using an external scheduler on a plan without five-minute jobs.
4. Reconciliation scans finalized payment-wallet history with stable pagination cursors, queues known signed invoice/claim signatures, fetches original finalized transactions and confirms exact invoice payments. It stores current wallet snapshots and price updates. Claims and invoice settlement are separate. Signed transaction requests are processed once; retries are for READ/verification only. The worker never signs, claims, refunds or sends SOL.
5. Inspect `/api/health` (database/fresh worker ≤10 minutes) and `/admin` sync failures. Failed signatures retry up to 12 times with bounded RPC timeouts. Use administrator `Retry verification only` / `Reconcile blockchain` or provide the ORIGINAL signature to the creator recovery form. Never ask someone to repay after an ambiguous submission failure. Expired quote recovery checks blockhash/finality/history; incomplete or busy evidence stays blocked for reconciliation.
6. Ordinary transfers lacking the invoice memo remain UNCLASSIFIED and do not credit orders. Wrong signer, recipient, amount, invoice, window, failed/unfinalized transactions and reused signatures are rejected for payment. Investigate accidental payments manually against the published refund policy; never relabel them paid to make the UI look complete.
7. Test authenticated webhook, duplicate delivery, cursor backlog, status health and receipt with your actual mint/wallet/providers before launch. Owner-approved mainnet tests are separate from the automated mocked suite. Do not run tests that broadcast real payment transactions automatically.

Official Pump layouts are vendored and pinned; shared recipient/admin proof and native SOL claims use the current official IDLs. Unsupported assets/layouts/authority modes fail closed. Connect an external monitor to worker/health alerts; email/SMS/partner API alert delivery is not implemented. No creator or payment-wallet private key belongs in Helius or AIRTIME.
